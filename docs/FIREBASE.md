`lib/firebase_options.dart` was generated by `flutterfire configure`. These files contain *client* API keys, which are designed to ship inside apps. If the repository is public, restrict the keys in Google Cloud Console → APIs & Services → Credentials (Android package + SHA-1, iOS bundle ID).

## ⚠️ One-time console steps you must do

1. **Link Google Analytics** (required for Analytics, the Realtime dashboard and Crashlytics breadcrumbs). It cannot be done from the CLI because you have to accept the Google Analytics terms.
   Firebase Console → ⚙ Project settings → **Integrations** → Google Analytics → **Enable** → choose or create an Analytics account.
   Then refresh the config files:
   ```bash
   flutterfire configure --project=mind-tiles-9t1li --platforms=android,ios --yes
   ```
   The configs currently show `IS_ANALYTICS_ENABLED=false` / no `analytics_service`. Until you link Analytics, events are logged by the app but don't appear in the console.
2. **iOS push: upload an APNs key.** Apple Developer → Certificates, IDs & Profiles → **Keys** → create a key with *Apple Push Notifications service (APNs)* → download the `.p8` file.
   Then go to Firebase Console → Project settings → **Cloud Messaging** → Apple app configuration → upload the key with its Key ID and your Team ID.
   Also enable the **Push Notifications** capability for the App ID. `ios/Runner/Runner.entitlements` already contains `aps-environment`.
3. **Crashlytics:** open Console → Crashlytics once. The dashboard activates after the first report arrives.
4. **Android release SHA-1** (optional, needed by some Firebase products): `cd android && ./gradlew signingReport`, then add the SHA-1 under Project settings → Android app.

## What the app sends

### Analytics (`FirebaseAnalyticsService`)
- **Custom events** (snake_case): `game_started`, `level_started`, `match_found`, `level_completed`, `level_failed`, `tutorial_completed`, `reward_claimed` and `achievement_unlocked`. Parameters are limited to mode, difficulty, level, moves, score, pairs and achievement ID. **No personal data.**
- **Automatic `screen_view`** for every named screen (`FirebaseAnalyticsObserver`): home, levels, modes, daily, settings, stats, achievements, about, tutorial, gameplay and results.
- Firebase also collects `first_open`, `session_start` and `user_engagement` automatically.

### Crashlytics (`CrashlyticsReporter`)
- `FlutterError.onError` reports framework errors as non-fatal. `PlatformDispatcher.onError` reports uncaught async errors as fatal. Native crashes are captured by the SDK.
- **Collection is off in debug builds.** Run `flutter run --dart-define=CRASHLYTICS_DEBUG=true` to test from debug. The About screen then shows a debug-only *Send test crash* button.
- Android symbol upload is handled by the Crashlytics Gradle plugin. On iOS, dSYMs are uploaded by the `flutterfire upload-crashlytics-symbols` build phase (needs `dart pub global activate flutterfire_cli` on the build machine).

### Performance (`FirebasePerformanceTracer`)
- Automatic: app start time, screen rendering (slow/frozen frames) and HTTP requests made by the SDKs.
- Custom traces:
  - `app_bootstrap`: from Firebase init to the first `runApp`.
  - `level_play`: one per board. Attributes `mode`, `difficulty`, `board` and `outcome` (won/lost/abandoned/restarted). Metrics `moves`, `pairs_matched` and `play_ms`.
- Data appears in Console → Performance after a few hours.

### Cloud Messaging (`FcmPushService`)
- **Opt-in only.** Settings → *Daily reminders* asks for OS permission (Android 13+ / iOS). The app never prompts at startup.
- When enabled, the device subscribes to topics **`daily_challenge`** and **`all_players`**. When disabled, it unsubscribes.
- Foreground messages are shown with `flutter_local_notifications` on Android (channel `mind_tiles_general`); iOS presents them natively. Background and terminated messages are shown by the OS.
- **Deep link:** add custom data `screen = daily` to open the Daily Challenge when the notification is tapped. The app never interrupts a game in progress.

## Realtime analytics / DebugView

- **Realtime:** Console → Analytics → *Realtime* shows users and events from the last 30 minutes (after Analytics is linked).
- **DebugView** (events within seconds, for development):
  - Android: `adb shell setprop debug.firebase.analytics.app com.codestack_mindtiles.game.mind_tiles_game` (turn off with `.none.`)
  - iOS: Xcode → Scheme → Run → Arguments → add `-FIRDebugEnabled`

## Sending a push notification

1. Console → **Messaging** → *Create your first campaign* → **Firebase Notification messages**.
2. Enter a title and text, for example "Your Daily Challenge is ready 🧩".
3. To test on one device, use *Send test message* with the FCM token. A debug build prints `[push] FCM token: …` to the console after you enable Daily reminders.
4. Target: **Topic** → `daily_challenge`.
5. Additional options → Custom data: `screen` = `daily`.
6. Optional scheduling: daily, in the user's local time zone.

## Privacy controls

- Settings → **Share usage & crash reports** (default on) switches Analytics, Crashlytics and Performance collection on or off immediately and persists the choice.
- Update the Play **Data safety** form and App Store **App Privacy**: analytics (app interactions), crash data, diagnostics (performance), device or other IDs (Firebase installation ID, advertising ID via AdMob). See `PRIVACY_POLICY_TEMPLATE.md`.

## Version notes

- FlutterFire is pinned to the generation that uses **Firebase iOS SDK 12.19.3** (`firebase_core ^4.15.2`, `firebase_analytics ^12.6.1`, `firebase_crashlytics ^5.4.1`, `firebase_performance ^0.11.7`, `firebase_messaging ^16.7.1`).
  The newer generation (firebase_core 5.x / iOS SDK 13.x) **requires Xcode 26.2+**, and this Mac has Xcode 26.1.1. After upgrading Xcode you can move to the latest versions with `flutter pub upgrade --major-versions`. firebase_messaging 17 replaces `getToken()` with `register()`/`onRegistered`.
- Firebase requires **iOS 15.0+**. The deployment target was raised from 13.0.
- All plugins build through Swift Package Manager, so CocoaPods is not needed.
